# Дизайн-система RWB Mesh

Основано на `ui-ux-pro-max` (product: Logistics/Delivery → Minimalism & Swiss + Flat;
dashboard: Data-Dense Dashboard + Real-Time Monitoring). Палитра: синий как основной
цвет маркетплейса, оранжевый — движение и рейсы, зелёный — доставлено и прибыль.
Фиолетовые градиенты и «стеклянные» карточки не используем: это операционный инструмент,
а не лендинг.

## Токены

| Токен | Значение | Где |
| --- | --- | --- |
| `colorPrimary` | `#2563EB` | главные действия, активная навигация |
| `colorSuccess` | `#16A34A` | выдано, прибыль, фильтр пройден |
| `colorWarning` | `#D97706` | внимание, неликвид, YELLOW |
| `colorError` | `#DC2626` | сбой, отказ, штраф |
| `colorInfo` | `#0EA5E9` | рейс в пути |
| `bg` | `#F4F6F9` | фон приложения |
| `surface` | `#FFFFFF` | карточки и таблицы |
| `ink` | `#0F172A` | заголовки, боковая панель |
| `muted` | `#52627A` | подписи, второстепенный текст |
| `border` | `#E2E8F0` | разделители |
| `orange` | `#EA580C` | акцент рейса, режим B |

Радиус 10–12 px. Тени не используем, разделяем границей 1 px.

## Типографика

- Интерфейс: **Inter**, база 14 px, строка 1.5; заголовки 20–24 px, вес 600.
- Числа и деньги: **JetBrains Mono**, `font-variant-numeric: tabular-nums`, чтобы
  колонки не «прыгали» между операциями.
- Не используем uppercase-подписи с трекингом и эмодзи вместо иконок.

## Правила экранов

- Сначала цифра, потом действие: KPI → таблица → кнопка.
- У каждого отказа решателя видно, какой фильтр не пройден и с какими числами.
- Статусы — точка + текст, без тяжёлых бейджей.
- Таблицы плотные: высота строки 40–44 px, заголовок `#F8FAFC`.
- Ошибки показываем рядом с действием (`message.error`), не только вверху страницы.
- Все суммы — в рублях с двумя знаками; копейки в БД, рубли в UI.
- Доступность: контраст ≥ 4.5:1, фокус видимый, интерактивные элементы ≥ 32 px,
  `prefers-reduced-motion` уважается (анимации только 150–250 ms).

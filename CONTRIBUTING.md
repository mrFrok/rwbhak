# Как мы работаем

## Ветки

- `main` — всегда рабочая версия, демо сдаётся отсюда
- `feature/<кратко>` — новая функциональность
- `fix/<кратко>` — исправления

```bash
git switch main && git pull
git switch -c feature/<кратко>
# ...работа...
git add -A && git commit -m "add <что сделано>"
git push -u origin HEAD
```

## Pull Request

1. Открыть PR в `main` сразу после первого коммита (draft) — чтобы все видели прогресс.
2. Описание: что сделано, как проверить, что осталось.
3. Ревью: минимум один апрув от другого участника.
4. Мерж — squash, ветку удалить.

## Коммиты

Коротко, в императиве, на английском: `add login endpoint`, `fix crash on empty list`.

## Задачи

Всё, что делаем, живёт в Issues с метками `bug`, `feature`, `docs`. Перед началом работы — назначить себя.

## Секреты

Ключи и токены — только в `.env` (в git не попадает) или в GitHub Secrets. Если секрет всё же попал в коммит — сразу сообщить в чат и перевыпустить ключ.
